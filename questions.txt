(1) The single process reaches a sampled peak RSS of 386,117,632 bytes.
(2) With five processes, peak RSS per instance ranges from 386,211,840 to 403,156,992 bytes. Memory per process stays roughly the same because each still has its own input and output buffers.
(3) mmap has lower PSS and USS because the processes share the input pages. Combined peak PSS drops from about 1.88 GB to 1.20 GB. The five normal processes take 10.96 seconds, while mmap takes about 7 seconds, or 10.35 seconds including conversion. mmap avoids reading each pixel separately and copying it into a private input buffer. Memory rises as the output fills, drops when the input is released, then stays flat while the output is saved. The benchmark files were in RAM because the server disk was full. The graph's time axis assumes 0.2 seconds per sample, so the log timestamps give a better measure of elapsed time.
(4) A major page fault needs the OS to fetch a page from its backing file or swap, usually involving disk I/O. A minor fault is handled without disk I/O, such as mapping a page already in RAM or allocating a zero-filled page.
